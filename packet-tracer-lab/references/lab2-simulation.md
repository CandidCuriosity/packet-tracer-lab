# 实验2：MAC学习与模拟取证

示例为四台PC与一台交换机，地址使用192.168.1.1–4/24。执行前沿用当前用户已确认方案，原文冲突先核对；MAC、帧数和点击次数以当前读回为准。

## 保住首次学习现场

先记录四PC真实MAC、端口、地址、链路和初始MAC/ARP，再原生保存无ping初始工程。
收敛阶段结束后进入暂停的Simulation，选择ICMP+ARP；观察完再做常规ping验收。
PC0→PC2首次ping入队后应先读回，区分被ARP缓冲的ICMP与真正发出的ARP；不以输入回执证明已发送。

待处理终端保持打开。不要为了截图用Alt+F4关闭正在ping的PC窗口，先移动或最小化并检查仍暂停。
关闭待处理终端可能使事件观察中断；事件消失或缓存已经改变时，不把缺失的阶段记为通过。
如果发生这种变化，保存中断现场并标未完成。用PT原生打开已保存的初始工程，重新检查MAC/ARP为空、
模式、过滤器和暂停状态，再做一次有独立证据的观察。只清MAC不足以恢复主机ARP与事件历史。
不把第一次中断与重试的trace拼接成一次完整观察。

## 每阶段读MAC与转发决策

1. 交换机收到PC0 ARP后，源MAC对应Fa0/1；同VLAN广播应从其余已连接端口发出。
2. PC2生成ARP回复后，交换机学习PC2→Fa0/3，回复定向到Fa0/1。
3. 已知ICMP单播从Fa0/1→Fa0/3，以实际协议、前一设备、入/出端口和Layer2决策确认。
4. PC1→PC3完成后，逐项匹配四PC实际MAC与Fa0/1–4，不只检查数量。
5. 使用当前IOS实际支持的show/clear命令。此次show mac-address-table显示4条DYNAMIC，
   clear mac-address-table接受后API和IOS均为空；其他IOS按帮助发现拼写。

PC1/PC3收到目标为PC2的ARP后正常丢弃，不代表链路故障。交换机处理自身未启用VLAN接口的ARP，
可出现忽略该ARP的决策，同时仍进行二层泛洪；按逐层决策区分本机处理与转发。

## Inspect可能显示旧表

已经打开的MAC Table窗口可能不刷新：API/IOS清空后，旧窗仍显示4条；学习增加后也可能仍显示1条。
先独立读API/IOS，关闭旧Inspect窗口，再从Inspect重新打开同一交换机MAC Table并截图。
截图前扩大MAC和Port列，验证完整内容可读；不能用截断文字证明具体端口映射。
不要因旧窗口未更新就重复clear、ping或改配置。

## 过滤器与历史事件游标

AT-SPI Toggle返回成功仍可能没改变勾选。读取最新树并看Event List Filters实际列表，必要时用最新截图整数坐标操作。
ICMP-only只是隐藏ARP，不证明ARP未发生或缓存已清空。

发广播之前保存过滤器、trace帧数、末帧index/sim_time、MAC/ARP与事件选择位置。
切过滤器后再保存一次基线；索引可能改变，不能直接沿用切换前的帧号。
切换过滤器可改变可见帧数和索引，一次Send只以切换后的基线识别新入队广播。
GUI Capture/Forward随后回放了旧事件；重复截图文件名或推进回执不证明新包经过交换机。

优先按原文GUI单步。若当前schema暴露pt_simulation_step等原生单步，可作为推进手段；
每次只前进一步，读回模式、事件与MAC，关键阶段仍截图。
只有越过新基线的事件及对应学习/转发变化才算本轮进展。
不要使用固定点击次数追过历史；以新增交换机事件、模拟时间和MAC学习变化作为进展。
若持续停留历史、状态矛盾或工具失败，停止并核对游标、暂停、bridge与进程；
不盲目循环、不重复Send、不用Realtime/fast-forward追过历史。需要对照时另开副本，明确记录改变。

## 广播与回复分别验收

广播从Fa0/1进入后，核对Fa0/2–4泛洪、三PC收到Echo Request、各自回复和PC0收到三个Echo Reply。
trace的顶层source/destination可能保留原PDU意图，回复仍显示PC0→255.255.255.255。
方向用实际包头（可取得时）、previous_device、in_port/out_port、协议与逐层决策交叉确认。
out_port可只列一个端口，泛洪的全部出口还需读Layer1发送决策。

终端回复可能受ARP缓冲，交换机忙出口也可缓存后发送；逐台跟踪至发送及PC0接受Echo Reply。
只检查当前新增帧的collision标记；没有标记时报告本次未观察到冲突，不推广到全部交换机场景。
buffered是阶段状态，继续跟到发送/接收，不立即当作失败；隐藏ARP时报告取证范围。

## 收尾与证据边界

观察完成后做最终Realtime连通性验收，保存每组原始命令输出；需要GUI截图时打开已有终端结果，
不要为展示重复发送流量。原生另存新工程，核对真实路径、文件大小、metadata和拓扑。
最终MAC会随时间变化。收尾为空可与动态老化相符，但没有计时/因果证据就不能确定原因，也不能反推阶段学习失败。
如果需重开验收，通过PT原生打开新副本并重新读配置/链路；未执行时单列未完成。
Word被用户暂停则保留草稿，网络验收与报告版式验收分别记录。
